# 增加一条轮足机器人（以 wheeled/atdog 为模板）

本文说明如何在 `robot_lab` 的 velocity-tracking 框架下新增一条**轮足狗**（腿用位置控制、轮用速度控制），
并以 `source/robot_lab/robot_lab/tasks/manager_based/locomotion/velocity/config/wheeled/atdog` 作为唯一参考模板。
目标产物与 `RobotLab-Isaac-Velocity-{Flat,Rough,Slope,Sand,Stairs}-ATDog-Dog-v0` 一样：可被 `gym.make` 创建，可直接用仓库训练脚本训练，并可对接部署侧。

---

## 1. 先理解模板的目录结构

```
config/wheeled/atdog/
├── __init__.py              # gym.register，5 个地形任务入口
├── rough_env_cfg.py         # 主模板：观测 / 动作 / 事件 / 奖励 / 课程 / 命令
├── flat_env_cfg.py          # 继承 rough，换平面、关高度扫描
├── slope_env_cfg.py         # 继承 rough，换地形与奖励权重
├── sand_env_cfg.py          # 继承 rough，障碍条地形与奖励权重
├── stairs_env_cfg.py        # 继承 rough，楼梯地形与奖励权重
└── agents/
    ├── __init__.py
    ├── rsl_rl_ppo_cfg.py    # 普通 PPO runner（Flat/Rough/Slope/Sand/Stairs 5 套）
    ├── rsl_rl_him_cfg.py    # HIM runner（history_length=6，5 套）
    └── cusrl_ppo_cfg.py     # cusrl TrainerCfg（5 套）
```

相关的公共定义：

- 环境与观测基类：`velocity/velocity_env_cfg.py`（`LocomotionVelocityRoughEnvCfg`、`ObservationsCfg`、`ActionsCfg`、`RewardsCfg`）
- 自定义观测/奖励函数：`velocity/mdp/observations.py`、`velocity/mdp/rewards.py`
- 机器人资产：`source/robot_lab/robot_lab/assets/atdog.py` 中的 `AT_DOG_CFG`
- URDF 数据：`source/robot_lab/data/Robots/atdog/dog/urdf/dog.urdf`（路径由 `robot_lab.assets.ISAACLAB_ASSETS_DATA_DIR` 拼接）

任务注册由 `robot_lab/tasks/__init__.py` 调用 `import_packages` 自动递归导入完成，新增目录不需要再改全局注册表。

## 2. 资产侧准备（URDF + ArticulationCfg）

### 2.1 关节命名约定

模板中关节分两组，顺序是**策略输入输出向量的一部分**：

```python
leg_joint_names = [
    "FR_hip_joint", "FR_thigh_joint", "FR_calf_joint",
    "FL_hip_joint", "FL_thigh_joint", "FL_calf_joint",
    "RR_hip_joint", "RR_thigh_joint", "RR_calf_joint",
    "RL_hip_joint", "RL_thigh_joint", "RL_calf_joint",
]
wheel_joint_names = [
    "FR_foot_joint", "FL_foot_joint", "RR_foot_joint", "RL_foot_joint",
]
joint_names = leg_joint_names + wheel_joint_names   # 共 16 个
```

新增机器人时：

1. URDF 中腿关节建议沿用同款命名，或者按需改名，但**必须同步修改以上三个列表和部署侧 `joint_names`**；
2. 轮关节必须是连续旋转关节（模板中是 `type="continuous"`），不要给它有限位；
3. 轮轴方向必须确认（URDF 里 4 个 `*_foot_joint` 的 axis 都是 `0 0 1`）。如果实机左右轮镜像安装，部署侧要在 `joint_mapping` 里做符号转换；
4. 记录 URDF 里的关节文件顺序。模板 URDF 顺序是 `FL, FR, RL, RR`，而配置向量顺序是 `FR, FL, RR, RL`，二者不一致，这会影响观测置零索引（见第 8 节）。

### 2.2 执行器配置

在 `source/robot_lab/robot_lab/assets/<robot>.py` 中新增 `ArticulationCfg`，参考 `AT_DOG_CFG`：

```python
actuators={
    "legs": DelayedPDActuatorCfg(
        joint_names_expr=[".*_(hip|thigh|calf)_joint"],
        effort_limit=23.5, velocity_limit=30.0,
        stiffness=35.0, damping=1.0, friction=0.0,
        min_delay=1, max_delay=2,
    ),
    "wheels": ImplicitActuatorCfg(
        joint_names_expr=[".*_foot_joint"],
        effort_limit_sim=23.5, velocity_limit_sim=30.0,
        stiffness=0.0, damping=0.8, friction=0.0,
    ),
}
```

含义：

- 腿：位置目标 + PD 跟踪，`kp=35`、`kd=1.0`，带 1–2 个物理步（5–10 ms）延迟；
- 轮：速度目标 + 隐式阻尼伺服，等效增益 `kd=0.8`、`kp=0`，速度上限 30 rad/s，力矩上限 23.5 N·m，无额外延迟；
- `init_state.joint_pos` 要包含 4 个 `.*_foot_joint: 0.0`（轮初始角度），左右腿 thigh 初始角符号相反（L=+0.8、R=-0.8）。

URDF 放到 `source/robot_lab/data/Robots/<robot>/urdf/`，在资产配置里用 `f"{ISAACLAB_ASSETS_DATA_DIR}/Robots/<robot>/urdf/<file>.urdf"` 引用。

## 3. 新增配置目录与任务注册

复制 `config/wheeled/atdog` 为 `config/wheeled/<new_robot>`，把类名里的 `ATDogDog` 替换为自己的前缀（例如 `MyRobot`），然后改 `__init__.py` 的 gym id：

```python
gym.register(
    id="RobotLab-Isaac-Velocity-Rough-MyRobot-v0",
    entry_point="isaaclab.envs:ManagerBasedRLEnv",
    disable_env_checker=True,
    kwargs={
        "env_cfg_entry_point": f"{__name__}.rough_env_cfg:MyRobotRoughEnvCfg",
        "rsl_rl_cfg_entry_point": f"{agents.__name__}.rsl_rl_ppo_cfg:MyRobotRoughPPORunnerCfg",
        "rsl_rl_him_cfg_entry_point": f"{agents.__name__}.rsl_rl_him_cfg:MyRobotRoughHIMRunnerCfg",
        "cusrl_cfg_entry_point": f"{agents.__name__}.cusrl_ppo_cfg:MyRobotRoughTrainerCfg",
    },
)
```

Flat / Slope / Sand / Stairs 各自注册一条，注意 `env_cfg_entry_point` 指到对应地形类。
四个 entry point 都可以保留；不用的算法可以删掉对应键，但训练脚本的 `--agent` 必须与留下的键一致。

## 4. `rough_env_cfg.py` 主模板逐项说明

### 4.1 类骨架

```python
@configclass
class MyRobotActionsCfg(ActionsCfg):
    joint_pos = mdp.JointPositionActionCfg(asset_name="robot", joint_names=[""], ...)
    joint_vel = mdp.JointVelocityActionCfg(asset_name="robot", joint_names=[""], ...)

@configclass
class MyRobotRewardsCfg(RewardsCfg):
    joint_vel_wheel_l2 = RewTerm(func=mdp.joint_vel_l2, weight=0.0, params={...})
    joint_acc_wheel_l2 = RewTerm(func=mdp.joint_acc_l2, weight=0.0, params={...})
    joint_torques_wheel_l2 = RewTerm(func=mdp.joint_torques_l2, weight=0.0, params={...})

@configclass
class MyRobotRoughEnvCfg(LocomotionVelocityRoughEnvCfg):
    actions: MyRobotActionsCfg = MyRobotActionsCfg()
    rewards: MyRobotRewardsCfg = MyRobotRewardsCfg()
    ...
```

- `ActionsCfg` 基类只有一个 `joint_pos`，轮足机器人必须**新增** `joint_vel` term；
- `RewardsCfg` 基类没有轮部专用惩罚项，模板通过子类新增 3 个空 term，便于在 `__post_init__` 里按轮关节单独设权重。

### 4.2 `__post_init__` 中的处理顺序

1. **Scene**

```python
self.scene.robot = MY_ROBOT_CFG.replace(prim_path="{ENV_REGEX_NS}/Robot")
self.scene.height_scanner.prim_path = "{ENV_REGEX_NS}/Robot/" + self.base_link_name
self.scene.height_scanner_base.prim_path = "{ENV_REGEX_NS}/Robot/" + self.base_link_name
```

`base_link_name` 用于高度扫描、质量/质心随机化和 base 相关奖励；`foot_link_name = ".*_foot"` 用于接触、滑足、腾空等奖励。

2. **Observations**

- `policy.joint_pos` 和 `critic.joint_pos` 的 func 都改成 `mdp.joint_pos_rel_without_wheel`，并传 `wheel_asset_cfg = SceneEntityCfg("robot", joint_names=wheel_joint_names)`；
- `policy` 与 `critic` 的 `joint_pos/joint_vel` 的 `asset_cfg.joint_names` 都改成完整 `joint_names`；
- 缩放：`base_ang_vel=0.25`、`joint_pos=1.0`、`joint_vel=0.05`（critic 侧基类已是 0.25/1.0/0.05）；
- 关闭 `policy.base_lin_vel`、`policy.height_scan`、`critic.height_scan`，使策略只依赖机载 IMU + 关节反馈；
- 关闭地形课程、命令课程（模板中设为 `None`）。

3. **Actions**

```python
self.actions.joint_pos.scale = {".*_hip_joint": 0.125, "^(?!.*_hip_joint).*": 0.25}
self.actions.joint_vel.scale = 5.0
self.actions.joint_pos.clip = {".*": (-100.0, 100.0)}
self.actions.joint_vel.clip = {".*": (-100.0, 100.0)}
self.actions.joint_pos.joint_names = self.leg_joint_names
self.actions.joint_vel.joint_names = self.wheel_joint_names
```

腿走位置、轮走速度，动作向量共 16 维：0–11 是腿，12–15 是轮。

4. **Events**

模板用较大的初始姿态扰动（roll/pitch ±0.8 rad）提升鲁棒性，只随机化 base 质量/质心，外力扰动只施加到 base。新增机器人可先原样复用，再按实机质量范围调整。

5. **Rewards**

轮足任务需要重点核对的项：

| 项 | 对象 | 模板权重 | 作用 |
|---|---|---|---|
| `joint_torques_l2` | 腿 | -2.5e-6 | 腿部能耗 |
| `joint_torques_wheel_l2` | 轮 | -0.4 | 轮部力矩惩罚 |
| `joint_vel_wheel_l2` | 轮 | -2.5e-2 | 限制轮速 |
| `joint_acc_wheel_l2` | 轮 | -2.5e-6 | 轮速平滑 |
| `joint_vel_limits` | 轮 | -4.0 | 轮速接近上限惩罚 |
| `wheel_vel_variance` | 轮 | -0.2 | 四轮绝对速度一致性 |
| `feet_slide` | foot body | -3.0 | 抑制滑移 |
| `feet_gait` | foot body | 2.0 | 对角步态同步 |
| `track_lin_vel_xy_exp` / `track_ang_vel_z_exp` | base | 50 / 70 | 速度跟踪主奖励 |

最后调用 `self.disable_zero_weight_rewards()`，把权重为 0 的 term 置空（注意：该调用只在类名严格等于当前配置类时执行，子类需在自己的配置里显式调用）。

6. **Terminations / Commands**

模板关闭 `illegal_contact` 终止、`command_levels` 课程；速度命令范围为 `lin_vel_x/y ∈ [-1,1]`、`ang_vel_z ∈ [-1,1]`（定义于公共 `CommandsCfg`）。

## 5. 观测与动作契约（训练与部署必须一致）

### 5.1 Policy 观测：57 维

| 顺序 | 项 | 维度 | scale | 备注 |
|---|---|---|---|---|
| 1 | `base_ang_vel` | 3 | 0.25 | 机体系角速度，IMU gyro |
| 2 | `projected_gravity` | 3 | 1.0 | 由姿态四元数得到 |
| 3 | `velocity_commands` | 3 | 1.0 | $v_x, v_y, \omega_z$ |
| 4 | `joint_pos` | 16 | 1.0 | 12 腿相对默认位姿 + **4 轮恒为 0** |
| 5 | `joint_vel` | 16 | 0.05 | 12 腿速度 + **4 轮真实角速度 rad/s** |
| 6 | `actions` | 16 | 1.0 | 上一帧裁剪后的原始网络输出 |

`base_lin_vel` 与 `height_scan` 已关闭。**轮子不需要位置观测**，但必须有轮速反馈。

### 5.2 动作：16 维

- `0–11` 腿位置动作：目标 = `default_joint_pos + scale * a`，hip scale 0.125，thigh/calf scale 0.25；
- `12–15` 轮速度动作：目标 = `5.0 * a`，单位 rad/s，轮 `kp=0`、`kd=0.8`。

### 5.3 部署必须复现的内容

1. 按同一顺序组装 57 维观测，关节顺序 `FR/FL/RR/RL`；每帧先乘 scale 再堆历史；
2. `dof_pos` 的轮 4 维强制置 0，绝不能把累积轮角度喂进网络；
3. `dof_vel` 必须提供真实的 4 路轮速，rad/s，符号与 URDF 一致，再乘 0.05；
4. `actions` 观测存**裁剪后的原始动作**（未乘 action scale），先 clip 再记录；
5. 输出动作先乘各自 `action_scale`，位置加 default offset；轮速指令限幅 ±30 rad/s（训练 action clip 是 ±100，不额外限幅会发出 500 rad/s 的非法指令）；
6. 控制频率 50 Hz（`sim.dt=0.005`，`decimation=4`）；轮速环带宽要明显高于 50 Hz，延迟要小，因为仿真里的轮是无延迟隐式速度伺服；
7. 力矩上限核对：仿真 `effort_limit_sim=23.5` N·m，而部署侧 `AT_sim2real/policy/atdog/base.yaml` 中轮 `torque_limits` 是 2.0 N·m，两者相差一个数量级，越障能力会不同；
8. 若部署 HIM 策略，`agents/rsl_rl_him_cfg.py` 中 `history_length=6`，输入需是 6 帧观测堆叠；单帧 PPO 配置（57 维）不能与 HIM 权重混用。

这些 scale 位于观测/动作管理器中（`actor_obs_normalization=False`），**不在导出的网络内部**，部署侧必须手动实现一遍，且不能重复施加。

## 6. 地形变体怎么做

不要复制整份 `rough_env_cfg.py`，继承即可。以 `flat_env_cfg.py` 为例：

```python
@configclass
class MyRobotFlatEnvCfg(MyRobotRoughEnvCfg):
    def __post_init__(self):
        super().__post_init__()
        self.rewards.base_height_l2.params["sensor_cfg"] = None
        self.scene.terrain.terrain_type = "plane"
        self.scene.terrain.terrain_generator = None
        self.scene.height_scanner = None
        self.observations.policy.height_scan = None
        self.observations.critic.height_scan = None
        self.curriculum.terrain_levels = None
        if self.__class__.__name__ == "MyRobotFlatEnvCfg":
            self.disable_zero_weight_rewards()
```

`slope/sand/stairs` 变体是在子类里替换 `scene.terrain.terrain_generator`（自定义 `TerrainGeneratorCfg`）并调整部分奖励权重，例如 sand 变体把 `base_height_l2` 提到 -300、`lin_vel_z_l2` 放宽到 -10、`ang_vel_xy_l2` 放宽到 -0.15，以适配条状障碍地形。新增地形时同样只覆写差异项。

## 8. 已知坑：轮位置置零的索引语义

`velocity/mdp/observations.py` 中的 `joint_pos_rel_without_wheel` 目前是这样写的：

```python
joint_pos_rel = asset.data.joint_pos[:, asset_cfg.joint_ids] - asset.data.default_joint_pos[:, asset_cfg.joint_ids]
joint_pos_rel[:, wheel_asset_cfg.joint_ids] = 0
```

`joint_pos_rel` 的列顺序来自 `asset_cfg.joint_names` + `preserve_order=True`，即配置的 `joint_names` 顺序；
而 `wheel_asset_cfg.joint_ids` 是关节在 articulation 里的**资产索引**（URDF 文件顺序）。
只有当二者顺序一致时，这个置零才落在第 12–15 列。

模板里配置顺序是 `FR, FL, RR, RL`，URDF 顺序是 `FL, FR, RL, RR`，**并不一致**。如果仿真里资产关节顺序就是 URDF 顺序，那么实际被置零的是 `FL_hip / RR_thigh / RL_calf / RL_foot` 这几列，而 `FR/FL/RR` 三个轮的真实转角会混进观测，与部署侧“12–15 置 0”的行为冲突。

新增机器人时必须验证一次：

```python
print(env.scene["robot"].joint_names)
print(env.scene["robot"].find_joints(["FR_foot_joint", "FL_foot_joint",
                                      "RR_foot_joint", "RL_foot_joint"]))
```

若顺序不一致，建议把置零索引改成“轮关节名在 `joint_names` 中的位置”：

```python
wheel_cols = [self.joint_names.index(n) for n in self.wheel_joint_names]  # [12, 13, 14, 15]
```

或改写 `joint_pos_rel_without_wheel`，使它用 `asset_cfg.joint_names` 来定位轮关节列，而不是用资产索引。这是 sim2real 观测一致性的必要检查项。
