奖励竞争

1. 实现层面的局部冲突已修复。在上 12 cm 台阶、摆动进度 0.95 时，原始
   swing 轨迹目标约 0.130 m（相对低支撑面）；若仍在边缘附近，edge 项要求
   >=0.145 m。两项对同一足端给出冲突目标。现在共享 world-frame 边缘安全高度，
   在原有边缘窗口内 swing 目标不低于 edge 目标。窗口之外保留原轨迹，
   权重、观测、PPO 和动力学不变。回归测试验证晚摆动时两项可同时达到零惩罚。
2. 该次训练线速度/角速度跟踪权重分别为 +60/+50，std 都为 0.5；五项楼梯项
   为 -5/-3/-2/-1/-50。长度/力误差的归一化不同，不能仅比权重绝对值。
   用户 3267 次日志中，两个 tracking 贡献共 +72.6992，五项楼梯惩罚合计
   -2.2415，约为前者的 3.1%。这些是同口径日志量的相对幅度，不能替代梯度分析。
3. 楼梯命令 yaw=0；角速度跟踪在机器人不前进、仅保持不转动时仍有高分。
   例如身体直立、命令 vx=0.25、实际速度为零时，仅两个 tracking 原始加权项
   就约为 60*exp(-0.25^2/0.5^2)+50=96.73（未乘 dt、未扣其他惩罚）；
   完美跟踪是 110。因而低速命令下停滞仍可能得到较高奖励。
4. 五项楼梯奖励全是惩罚；减少运动可减少关节加速度、动作变化和撞击成本，
   没有直接的跨越进展正奖励。`stair_progress` / `stair_success` 是指标和课程依据，
   不会自动进入 PPO reward。高总奖励不能证明爬楼更好。
5. `stand_still` 仅在近零命令启用，不直接阻碍移动命令的跨越。
   `joint_pos_penalty`、joint_acc、动作平滑项会约束抬腿动作幅度/加速度；
   当前 joint_acc 约 -8.35，大于五项楼梯惩罚之和，需要通过分项消融确认影响。
   generic swing/gait/slide/base-height/stumble/contact-forces 已由五项体系替换，
   没有发现这些旧项仍重复计分。
6. 速度 tracking 使用机体系，楼梯几何/足端速度/力使用世界坐标；几何前视方向
   由机体系命令经 yaw 旋转到世界系，不直接混比两种坐标。机身倾斜时 body-frame
   tracking 和水平地形目标仍有设计差别，但这不是坐标计算错误；不要在本轮
   无评估的情况下同时切换速度奖励坐标系与 HIM 的速度监督坐标系。

后续奖励实验建议：先单独验证上述轨迹修复；再比较 yaw 权重 50→20 的实验，
同时保留线速度跟踪。若仍停滞，再引入有界、按控制步差分的实际前进/上升奖励，
对静止命令、reset 和失败情况显式处理。不要每步奖励累计 stair_progress，
避免停在已获得进度的位置重复获利。所有候选均需固定高度/方向/种子评估；
本次没有盲目叠加权重改动，也没有声称恢复训练质量。

HIM 观测与策略链路

|项目|checkpoint / 保存配置与当前代码核对|
|---|---|
|Actor 历史输入|282 = 47 × 6|
|47 维单帧|phase 2 + ang_vel 3 + gravity 3 + command 3 + joint_pos 12 + joint_vel 12 + action 12|
|历史顺序|oldest_to_latest，Actor 取最后 47 维|
|Critic|50 维；base_lin_vel 位于 [0:3]；无 critic height scan|

|估计器输出|直接使用监督尺度（2×m/s），Actor 和导出均不额外乘/除 2|
|噪声|训练 Actor 有噪声，clean Critic 无噪声；这是学生/教师设计差异|

训练分布均值、act_inference、导出 forward 和 TorchScript 使用同一历史张量
及相同 checkpoint 参数，对 64×282 的合成历史输入最大绝对动作差均为 **0**。
这证明这些代码路径的一致性，不验证外部硬件部署的传感器缩放/历史组装，
也不等价于完整仿真轨迹评估。ONNX runtime 未单独运行。

估计 MSE≈0.018 对应缩放空间 RMSE≈0.134，除以 2 后约 0.067 m/s，
是三轴 next-step 标签的训练批次误差量级；不是命令速度跟踪误差。
不能仅由该 loss 推断 Actor 已正确完成上楼任务。
